# Application architecture

`src/app` is the composition boundary between DSH and the voice-domain modules. Client and server entry points remain separate; host-only Node dependencies must never enter the browser bundle.

- `client/apply.tsx` injects DSH client services, creates session controllers and voice ownership, wires engines and settings, and disposes resources. `client/slotDefinitions.ts` and `client/registerSlots.tsx` own the established slot IDs, order, and registration. Preserve those contracts when changing placement. Microphone mode stop invalidates pending input ownership and application continuity without ending current playback; explicit takeover and full End retain their separate handoff/lifecycle semantics.
- `server/apply.ts` composes host engines and providers. `server/registerRoutes.ts` registers authenticated same-origin routes; do not bypass their validation or expose host access directly to browser code.
- `client/transcriptionLeaveGuard.ts` owns one activity-scoped native `beforeunload` listener across microphone, meeting sources and Settings test capture. It covers acquisition, listening and unsettled transcription, not playback or voice-mode preference alone. Cancelling the browser dialog does not stop capture; existing `pagehide` cleanup runs only after leaving. Idle and disposed apps remove the listener. Browser wording, user-activation requirements and mobile/forced-close limitations apply; this is not refresh recovery.
- `client/i18n` owns the only UI translation tree: typed, alphabetized catalogs for every supported locale, runtime selection synchronized with `ctx.locale`, DSH registration, and the boundary wrapping slot components. UI language must not change STT/TTS language or user-defined command phrases.
- `server/browserAsrAssets.ts` exposes exact packaged worker and matching ONNX runtime files behind versioned authenticated routes. `client/apply.tsx` owns one browser model manager across Settings and independent capture sources, disposing it only with the application. Model weights are downloaded directly to browser-profile storage after explicit consent; host routes never proxy audio or arbitrary model/filesystem paths.
- The existing composer-right slot keeps shared audio independent. MeetingToggle opens a source menu without capture. Its Meet quick form contains only URL and text Connect; the explicit action calls connectMeeting with the persisted Settings name/origin and host-saved key, ensuring reception before one join request. No name override, credential input, configuration icon or local dialog belongs to the composer. Active bot control/status has one compact menu surface; MeetingBars renders only audio sources. Closed critical feedback uses a localized trigger label/title and visible indicator.
- Styles are assembled from `src/styles/index.ts`; design-system primitives live under `src/shared/design-system` rather than here.

Read [the repository overview](../../../../docs/ARCHITECTURE.md) for dependency direction and stable contracts, and the relevant module architecture before editing feature behavior. Read [application agent guidance](AGENTS.md) for operational constraints.
Experimental Attendee composition uses webServer.registerUpgrade for external token-authenticated ingress and connection.fetch.register for owner-authenticated browser control/PCM batches. Host API keys are persisted separately from preferences in a fixed host-owned plaintext 0600 credential file bound to normalized loopback API origins. Authenticated browser metadata exposes only key presence; open uses the exact-origin stored key when none is supplied. Existing leases retain their original in-memory key even after replacement/deletion until lease expiry or release. Only loopback Attendee API origins are allowed. HTTPS/direct receivers keep explicit certificate/reachability requirements. For HTTP local installs, a verified Connect uses the packaged Compose audio bridge: fixed loopback certificate discovery, per-connection TLS trust and authenticated receiving WebSocket. Compose provisions its own certificate/worker trust bundle; no host listener, global trust mutation or Docker process control belongs to the plugin.
