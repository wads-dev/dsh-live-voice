# Core voice domain

`mutedSpeechWarning.ts` owns an four-second continuous detected-speech clock per input. Coordinator patches re-evaluate it; only engine onActivity drives explicit `inputSpeechActive`, independently of result chunks and transcription backlog. Before first display, silence resets the speech timer; after display, a three-second trailing-silence debounce avoids flicker and resumed speech cancels hiding. Lifecycle transitions clear immediately. No recognized text is required or retained, and no automatic unmute occurs. Shared input policies use the same activity contract.

`timestamp.ts` owns the pure local-clock formatter and normalization: date parts, seconds and separators are optional; hours/minutes remain mandatory. Defaults preserve the legacy format.

`core` owns policy and reusable voice-domain state, not DSH slot/route registration or provider-specific presentation. `coordinator.ts` serializes input transitions, owns conversation state and speech queues, and invalidates stale async work with generations. `ownership.ts` arbitrates microphone and speaker use between sessions and Settings self-tests. `transcript.ts` enforces append-only final recognition text (interim hypotheses never own or rewrite composer content), `microphone.ts` manages capture and activity, `filters.ts` handles voice commands and speech text filtering, and `settings.ts` normalizes persisted values and defaults.

Recording-backed conversation input can be parked by `pauseInputForNavigation()` without aborting recognition or sealing its writer. Final recognition callbacks remain on the original coordinator and are queued while detached; `resumeInputFromNavigation()` delivers them only after composition reacquires hardware ownership and a current composer. Navigation generations reject obsolete resume completions. Stop/End/disposal clears that queue and releases input; native Browser recognition keeps its existing teardown path. Parked capture retains its start-time recognition configuration and does not retry acquisition in the background.

Recording audit emits transition-only assistant wait start/end with bounded reason codes, queue/request counts and delay, playback admission, requested input gating, recognition/meter stop completion or failure, real engine playback start/end, cancellation and errors. Input-stop completion means adapter promises settled successfully, not independent physical microphone proof. Wait reasons never include text, message IDs, provider errors, or audio. Event audit does not change capture/recognition/playback policy.

The `qwen/` subtree contains shared Qwen host configuration and its settings UI; recognition and speaking adapters live in their respective modules. Keep the client/host dependency graphs separate. Preserve the persisted `dsh-live-voice.settings` key and normalization compatibility. `startConversation()` enables input without cancelling playback; `stopConversationInput()` retires input without clearing accepted speech. Speaker-mode starts defer capture until playback finishes, while `takeMicrophone()` retains the explicit teardown-before-capture handoff. Full `endConversation()` remains the global lifecycle/End-command operation. Automatic speech admission depends on the assistant-speech preference, not microphone conversation mode; new segments and accepted queues continue with input closed. Distinguish capture, recognition, playback, and generation; do not conflate pausing with cancellation or resume obsolete speech after a new turn. Consult [voice lifecycle](../../../../../docs/VOICE-LIFECYCLE.md) for expected transitions.
