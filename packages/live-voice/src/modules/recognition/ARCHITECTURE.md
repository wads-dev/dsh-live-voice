# Recognition module

`engines/browser/BrowserRecognitionEngine.ts` adapts browser speech recognition and reports local-pack/browser capabilities. `engines/qwen/QwenRecognitionEngine.ts` and `engines/whisper/WhisperRecognitionEngine.ts` adapt local-first HTTP recognition; host bridges live beside the relevant adapters (Whisper here, shared Qwen configuration in `../core/qwen`). `components/RecognitionCapabilityStatus.tsx` and engine settings UI present capability and configuration states.

`vad/` owns the experimental browser Silero pool, worker inference, AudioWorklet capture and streaming resampling. Silero is the default; missing assets or exhausted recovery of selected Silero fail capture explicitly. Recording-owned initialization/live failures receive at most two reattachments; successful inference resets that budget without switching detectors. Only explicit `voiceDetectionEngine: "energy"` uses energy detection. One lazy inference session serves independent source states and bounded fair queues. Model/runtime assets are packaged and exposed by the application boundary; HTTP engines use the recording-owned pipeline: raw PCM enters the recorder before classification, VAD hysteresis confirms sparse speech/silence pins, and transcription queues carry sample-range references rather than PCM chunks. See [Recording](../recording/ARCHITECTURE.md). HTTP engines never own tracks. See [Silero VAD](../../../../../docs/SILERO-VAD.md).

`transcriptionContext.ts` defines the optional HTTP recognition hint (1,000 characters, no NUL). The shared `recognitionContext` preference starts empty; HTTP capture sends only nonempty text in a percent-encoded `x-dlv-transcription-context` header alongside the unchanged WAV body. Authenticated host routes reject malformed context with 400, then Whisper/Qwen adapters forward it as the standard `prompt` field (multipart or OminiX JSON). No automatic retry drops the hint. This is not agent context or a language allow-list, and provider support must not be assumed. Browser-native and browser-local inference do not consume this HTTP setting.

`local/` owns allowlisted pinned model metadata, explicit streamed browser-profile cache downloads, a shared model lifecycle service, cache-only worker inference, and browser-local recognition adapters. Whisper uses Transformers.js; Qwen implements the documented ONNX layout-v2 contracts independently. A real WebGPU adapter is required for Qwen; Whisper offers explicitly selected WASM. Nothing silently switches to HTTP or downloads weights during capture. The same recording-owned pipeline feeds bounded PCM ranges; worker termination cancels otherwise non-abortable inference. See [Browser ASR](../../../../../docs/BROWSER-ASR.md).

Shared Browser recognition borrows the meter-owned live audio track and reuses it across native restarts/reset; it never stops that track. External-audio support is independent of local-pack availability and remote-processing opt-in. A bounded same-origin srcdoc probe first verifies a known, denied microphone Permissions Policy, then uses the frame constructor and an ended synthetic canvas video track: only synchronous InvalidStateError validates the overload. Legacy ignored arguments, missing policy introspection, CSP/DOM failures and cancellation fail closed; start.length and OS/UA are not capability signals. The probe aborts immediately and releases its own frame/track. Meeting discovery happens before meter.start; native recognition begins only after capture provides the track.

Distinguish microphone capture and permission from recognition engine availability. Do not infer feature support merely from operating system. Bound audio and host requests, keep host-only code out of the browser bundle, and abort/ignore stale results after cancellation. Recognition language and voice-command phrases are independent of the interface locale. Browser simulations are not a physical microphone or model acceptance test.
