# Recording module

This browser-only module owns recording sessions, speech/silence pin markers, recognition attempts, and compressed audio storage. Recognition engines append the continuous captured mono sample line; they do not archive duplicate chunk PCM or own pin/attempt metadata. Composition and UI registration remain in the application.

## Storage and sample mapping

- `PinDetector` retains only confirmed transitions with their marked/confirmation positions. `RecordingRecognition` attaches one capture per source, appends raw samples before VAD, closes segments on silence pins and splits long speech into bounded range requests without inventing pins. Chunk boundaries do not imply paragraphs. On the next speech pin, the sample-clock silence duration selects paragraph-before metadata independently of the chunk threshold; bounded max-length requests never invent paragraphs. Attempts retain this flag and actual speech onset for audit and timestamp delivery. Capture finish drains the worklet before sealing; cancellation discards delivery but preserves already captured audio and audit.
- The repository factory is lazy: construction never asks for permissions or opens storage. Recording is enabled by default (opt-out); an enabled begin uses IndexedDB and may request browser persistent-storage protection. The session's persistent flag reports the browser's protection grant, not a promise that best-effort IndexedDB cannot be evicted.
- Native WebCodecs Opus encoding/decoding is capability-checked before beginning, including non-persistent sessions. Missing codec, Web Locks, IndexedDB, quota, and encoding failures are explicit structured errors, never a silent WAV or memory fallback.
- A one-second PCM accumulator is encoded as independent pages. A read flushes a partial page first. Each page carries its own decoder configuration, packet timestamps, lookahead, exact captured sample count, and bounded drain tail. Decoder lookahead and final padding are trimmed to the captured sample line. Exactly-zero PCM may omit payload, but never omits timeline samples. No per-frame VAD probabilities are retained.
- IndexedDB commits each encoded page and session sample counters together in one strict-durability transaction. Metadata writes always read/modify/write in the transaction, so a late page write cannot erase an attempt or pin. Read cursors fetch only intersecting pages; decoding keeps one page at a time. Playback WAV is generated on demand in bounded decode windows and is never stored; explicit long-session playback/export may still allocate a large Blob.
- Active persistent writers hold a per-recording Web Lock. One recovery pass per repository lifetime seals orphaned recording metadata as interrupted while leaving genuinely active tabs untouched. Only committed pages are available after a crash; pins beyond that saved range are discarded. There is no fabricated audio tail.

Transcription ranges have an 800 ms minimum safety margin on both sides (`TRANSCRIPTION_BOUNDARY_MARGIN_MS`), preserving larger configured margins. Range descriptors wait for captured post-roll outside the PCM write queue, so silence confirmation or a max-length split cannot launch early or deadlock appends. Pending context blocks delivery/playback. Capture finish clips to available samples and releases pending ranges; stop discards them. VAD pins, speech-onset timestamps and paragraph classification retain their original boundaries. Overlap is intentional and may repeat words. Browser-local chunk limits include both margins.

Saved `audioBytes` counts encoded packet bytes and decoder descriptions, committed atomically with each page. It excludes IndexedDB overhead, recording metadata and unsaved PCM. Legacy recordings are measured via page cursors without decoding and cached by saved sample count. Totals use the full session list, independent of source filters.

## Ownership and limits

Processing notifications separate `transcribing` (queued plus active speech attempts), `deliveryPending` (those attempts plus unsettled speech-boundary writes and capture finish), and aggregate `pending` (all serialized writes). Only speech attempts drive visible transcription status. Automatic delivery waits for `deliveryPending`, not recurring silent PCM writes; Hold-to-Talk release, playback admission and page-leave protection still wait for aggregate work. Legacy engines without the delivery field conservatively use aggregate pending. Continuous silent PCM persistence must neither announce transcription nor reset the send countdown.

Append, pin, attempt, read and finish operations are serialized per writer. Append owns a copy of its input and rejects more than eight seconds of queued PCM as backpressure rather than buffering indefinitely. Finish immediately seals further audio and pins, drains accepted appends, flushes the partial page, then releases ownership. Attempt upserts may still settle after audio is sealed, for already-running recognition requests. Dispose interrupts and drains active writers before closing storage.

Explicit opt-out writers run the same codec pipeline in a non-persistent compressed memory store with a shared 32 MiB page budget. Crossing that budget fails explicitly; it never silently drops earlier ranges. Long-running opt-out sessions therefore must handle memory-limit errors (or finish and release older runs). User-requested range PCM/WAV and full JSON export allocations are outside the steady-state capture budget.

Legacy retention counts the newest N ordinary finished sessions independently per type (microphone and shared), regardless of sourceId; N defaults to one. New Attendee metadata instead groups all participant UUIDs and capture bursts by the explicit bot/group ID. The same setting retains N ordinary groups per storage backend, ordered by their latest capture activity, never by inferred Meet state. Every burst and participant in a retained group survives together. An active writer, pending attempt or starred member protects its whole group without consuming ordinary slots. Silence between bursts does not reserve a group: another newer meeting may evict a quiet group, and later resumed capture starts new history without restoring evicted recordings. This is bounded by group count, not bytes or call duration, and is not a backup. Browser quota failures, the opt-out memory budget and append backpressure remain explicit. Legacy sessions without participant metadata keep the old per-type behavior. Automatic group removal takes a namespaced group Web Lock plus every recording lock, and one conditional sessions/pages transaction rechecks complete membership and protections before deleting all members; changes or lock conflicts skip the whole group. Group creation uses the same group lock to avoid partial concurrent eviction. Active, pending-transcription and starred sessions survive without consuming slots. Star protection is stored atomically, exported, and may be removed; unprotecting runs cleanup immediately. Automatic removal rechecks current protection under the recording lock. Manual removal may delete starred sessions, rejects active runs, and atomically deletes payload pages and metadata. Star protection is not browser eviction protection or a backup guarantee. Starred sessions can have a trimmed, single-line name of up to 120 characters; atomic read/modify/write updates preserve names across page, attempt and event writes. Removing the star preserves the name but permits ordinary retention.

Assistant playback events are separate from VAD segmentation pins. A playback run binds current recording writers before speaker gating, allowing actual engine playback callbacks to append to the sealed microphone session. Events store wall-clock time and the captured sample boundary, never synthesized audio or invented samples during capture gaps. Capture start/end and speaker-gating requests remain distinguishable from actual playback.

Explicit archive retranscription uses an optional v1 service method, current HTTP recognition settings and minimum 800 ms margins. It requires sealed speech, holds the recording lock against deletion/retention, appends pending/success/error attempts without overwriting history, aborts with the inspector/repository lifetime, and never delivers to the composer. Older recording services remain inspectable without the action.

Recognized command events carry only a typed action plus the originating segment/attempt IDs, never the raw command phrase. A per-result acknowledgement records at most once; its recording-targeted timeline is bound before teardown, so a late final result cannot annotate a newer capture or another participant. Archive retries never execute commands. Recognition is not proof of action completion.

The event stream is distinct from VAD pins. Optional typed details describe assistant wait reasons, queued/pending counts, delays and admission outcomes. Event contexts are copied when emitted, use actual wall time plus the observed capture boundary, and remain exportable after sealing the bound capture. No older event or wait is reconstructed. Recognition/meter stop completion is adapter-level evidence, not proof from a physical device.

HTTP attempts also retain additive request metadata measured from the actual encoded browser-to-DSH WAV body: preparation time, payload bytes, input/output samples and sample rates, encoded duration, language and response status when available. The metadata is persisted before fetch and retained on errors; it contains no duplicate PCM/WAV or context prompt. It is not evidence of server receipt or model consumption, and excludes host JSON/base64/multipart repackaging. Historical attempts remain explicitly unmeasured.

The versioned JSON export is self-contained: recording metadata plus independent Opus pages with base64 decoder descriptions and packets. It may be large and is only assembled on explicit request. Subscribers receive invalidation callbacks, not audio/transcript logs. Raw recording content is never logged by default.
Attendee recordings carry optional additive `participant` metadata: provider, explicit bot/group ID, participant UUID, original name and optional alias. Display label and participant names are immutable capture-start snapshots; later API names or aliases update only subsequent captures, never historical sessions. Identity is never inferred by splitting the composite source ID. Legacy sessions without participant metadata remain valid version-1 records; exports preserve the captured metadata.

External PCM meters expose subscribePcm. RecordingRecognition appends each accepted frame before feeding a source-owned Silero stream (or the explicitly selected energy detector); no AudioContext or microphone recapture is involved. Sparse Attendee packet-idle boundaries finish actual capture and release ranges without synthesizing recorded silence.
